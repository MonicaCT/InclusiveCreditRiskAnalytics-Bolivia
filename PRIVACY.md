# Privacy, Ethics and Responsible Data Use

## Public-data rule

This repository may publish only branch-level analytical outputs, aggregate tables, dashboard figures and reproducible code. Officer-level names, direct identifiers, contact information, precise personal locations and free-text records must not be exported into public analytical files.

## Current source-data status

The raw workbooks include an officer/personnel sheet. The public pipeline intentionally avoids exporting those names and generates branch-level outputs only. The raw files are retained as source artifacts because they were already part of the public repository, but the analytical narrative and dashboard do not expose personal names.

## Why deletion is not enough

Removing a file in a later commit does not erase earlier Git objects, forks, caches or clones. If personal data are committed publicly, the response should include visibility restriction, history review, access review and a new privacy-safe release.

## Disclosure controls

- Publish branch-level aggregates rather than officer-level records.
- Keep observed history separate from business projections.
- Flag negative mora or overdue adjustments before interpretation.
- Avoid causal claims about poverty or inequality without household welfare data.
- Publish only the minimum data required to reproduce the dashboard.

## Analytical ethics

- Financial inclusion is treated as a development proxy, not as direct poverty measurement.
- Forecasts and stress tests are decision-support tools, not guarantees.
- Branch comparisons should be framed as access and risk signals, not rankings of communities.
- Interpret small-sample correlations as early-warning diagnostics only.
